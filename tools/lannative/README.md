# Loader source (`version.dll`)

`lannative.c` builds `version.dll`, a proxy DLL the game loads from its own folder. Every export is forwarded to the real
`System32\version.dll`. The loader inline-hooks game functions by RVA, does its work on the game thread inside a hook on
`UGameEngine::Tick` (wrapped in SEH), and refuses to patch when the live bytes differ from the expected ones. It only runs when the game was
started with `-NoEAC` (the launcher does that).

## Build

Needs MSVC Build Tools 2022 (x64) and your own copy of the game.

1. `symbols.bin` (symbol table for `hook_symbol` and the script extender) is made from the game's own PDB on your PC and is never shared:
   * build `tools\symtool` (`dotnet build -c Release`), then `symtool <path to Absolver-Win64-Shipping.exe> dumpall > symbols_all.txt`
   * set `ABSOLVER_GAME` to the game folder (the one with `Absolver.exe`), then `python gen_symbols.py symbols_all.txt symbols.bin`
     (needs `pip install pefile capstone`), run in this folder. Without arguments it prints its usage.
2. `build.bat` -> `version.dll`.
3. Copy `version.dll` next to `Absolver-Win64-Shipping.exe`, or use the installer in `tools\installer`.

`version_exports.h` (forwarders) and `lannative_targets.h` (hook targets with their expected bytes) are generated by `gen_headers.py` and are
already in the repository.

Mod-checking tools: `test\build_tools.bat` builds `reccheck.exe`, `modscan.exe` and `ueapply.exe`.

## Layout

* `lannative.c` - entry point, hooks, key handling, the world menu (F2) and loader window (F1).
* `*.inc` - units: one feature each (mods, rows.json, plugins, content kinds, powers, NPCs, bots, map scripts, ...), listed in `units.inc` (the item code's helpers `weapons.inc`, `weaponslot.inc`, `kindstate.inc`, `learn.inc` and `powers.inc` are included from `content.inc`).
* `*.h` - pure logic and tables used by the modules.
* `AbsolverSE.h` - the plugin API header (`docs/API-REFERENCE.md`).
* `lan_logic.c`, `lan_telemetry.c` - LAN play logic and its read-only logging (`docs/HOSTING.md`).

## Units and registration

Every feature is a unit: an `.inc` file listed once in `units.inc`, which `lannative.c` includes (one translation unit); the helpers of
the item code are included from `content.inc`. The order of
`units.inc` is the dependency order: a unit may use what the units above it define, so a new unit goes at the end.

A unit registers what it runs with a macro next to its own code instead of a call in `lannative.c`: `LN_PREINIT` / `LN_INIT` (start-up),
`LN_PRETICK` / `LN_TICK` (every frame), `LN_SE_TICK` (script extender frame), `LN_DRAW` (canvas text), `LN_API` (its `AbsApi` fields),
`LN_CONTENT` (content kinds), `LN_MODS_ROWS` (rows on the F1 Mods tab) and `LN_HS_VERB` (verbs on the host-mods side channel). The tables
are declared in `lnhooks.h`; `lnreg.h` is the mechanism (the linker collects the entries; the start-up, frame, draw, content and page tables run in the order of
an explicit four-digit key, and a key used twice in one table does not compile). The log lists every table after the version line (`registry: ...`).

## Keys

F1 opens the loader window (mods, keybinds, hosting, settings, log; `docs/MODS.md`), F2 the world menu (host, join, maps, NPCs). F9, F10 and F11 are developer keys,
active only while the file `LanNative\devkeys.txt` exists: F9 free camera (`LanNative\cam.txt`), F10 teleport (`LanNative\goto.txt`), F11 runs
the developer commands in `LanNative\lmtest.txt` (`docs/ADVANCED.md`).
